# ESP32-C6-N16 Miner Controller v3
Автономный аппаратный контроллер мониторинга и управления парком ASIC-майнеров (до 8 устройств) на базе микроконтроллера **ESP32-C6** (16 МБ Flash).

Проект предоставляет веб-интерфейс реального времени, встроенный кольцевой буфер системных логов (64 КБ) с фильтрацией по майнеру, автоматический сканер локальной подсети, механизм удаленной перезагрузки майнеров по различным протоколам (TCP API, HTTP REST, LuCI/CGI с поддержкой Digest и Cookie-авторизации), а также точку доступа с Captive Portal для первичного ввода в эксплуатацию.

## Ключевые возможности

* **Полная автономность:** Не требует внешних серверов, брокеров MQTT или облачных сервисов. Веб-интерфейс полностью вшит в память микроконтроллера (Flash PROGMEM).
* **Мониторинг метрик:** Хешрейт (мгновенный 5s, средний, 30m, паспортный), температуры плат и чипов, параметры блока питания (напряжение, токи, температуры зон PSU), обороты и процент заполнения ШИМ кулеров, счетчик Accepted/Rejected/Stale shares и процент брака, HW-ошибки, статус воркеров на пулах, энергоэффективность **J/TH**, средняя частота чипов.
* **Телеметрия по каждой хеш-плате (v2.2):** Отдельный блок по каждой из 4 хеш-плат: хешрейт платы (TH/s), количество активных чипов, HW-ошибки, градиент температур чипов (`temp_chip`), температура PCB, частота, признак «битые ASIC».
* **Расширенная телеметрия пулов (v2.2):** Статус `Alive`/`Dead`, флаг `Stratum Active`, URL, сложность (`Diff`), количество принятых/отклонённых/устаревших шар по каждому пулу (до 3 пулов).
* **Гибкая перезагрузка майнеров:** Реализован каскадный алгоритм отправки команд: от стандартного JSON-RPC на TCP 4028 до веб-вызовов CGI/LuCI через HTTPS с обходом самоподписанных сертификатов, генерацией сессионных cookies и расчетом MD5 Digest-авторизации (RFC 2617).
* **Автосканирование сети:** Функция сканирования подсети `/24` для автоматического обнаружения активных ASIC-майнеров.
* **Системный Ring Buffer логов (64 КБ):** Кольцевой буфер на 64 КБ в оперативной памяти с автоскроллом в веб-консоли, **фильтрацией по майнеру** (все / конкретный индекс) и возможностью выгрузки файла `.log` с меткой времени. Отдельно ведётся счётчик вытесненных (`overwritten`) байт.
* **Смена пароля веб-интерфейса:** Через настройки, с валидацией длины (8–64 байта UTF-8) и подтверждения. Применяется также к OTA. После смены ESP перезагружается.
* **Обновление по воздуху:** Интеграция `ElegantOTA` (через веб-интерфейс) и классического `ArduinoOTA`.
* **Диагностическая консоль:** Режим перехвата сырых ответов TCP/HTTP от майнеров (`LogTee`), с фильтром по индексу майнера.

## Поддерживаемое оборудование

1. **Antminer (Bitmain):**
   - Серия **S19** (S19, S19i, S19 Pro, S19j Pro, S19 XP и совместимые со стоковыми прошивками).
   - Серия **L3+ / L3++**.
   - Взаимодействие: сокет TCP `4028` (команды `summary`, `stats`, `pools`), fallback на веб-интерфейс (CGI / Digest auth).
2. **Whatsminer (MicroBT):**
   - Линейки **M30 / M50** (включая иммерсионные версии и кастомные прошивки, в частности **BiXBiT**).
   - Взаимодействие: TCP `4028` с адаптивным парсингом. Для BiXBiT вместо команды `stats` используется `devs` (для получения температур по платам). Дополнительно: BiXBiT HTTP REST API (`/api/system/status`, `/api/pools`), HTTPS LuCI restart (`/cgi-bin/luci`).

## Аппаратные и программные требования

### Аппаратная часть
* **Плата:** ESP32-C6 Dev Module (вариант **N16** с 16 МБ Flash-памяти).
* **Питание:** Стабильный источник 5V / 1A (Type-C или пин 5V/VIN).
* **Сеть:** Wi-Fi 2.4 ГГц в одном широковещательном сегменте/VLAN с майнерами (для корректной работы автосканера и доступа к локальным портам).

### Программная среда
* **Arduino IDE** (версии 2.x) или **PlatformIO**.
* **ESP32 Core:** версия `>= 3.0.5` (поддержка архитектуры RISC-V ESP32-C6).
* **Зависимости из Library Manager:**
  - `ArduinoJson` (Benoit Blanchon) `>= 7.2.0` (**критично: версия 7.x** — используется `JsonDocument`).
  - `ElegantOTA` (Ayush Sharma) `>= 3.1.1`.
* **Встроенные библиотеки ядра (не требуют установки):**
  - `WiFi`, `WebServer`, `HTTPClient`, `WiFiClientSecure`, `DNSServer`, `Preferences`, `ESPmDNS`, `ArduinoOTA`, `freertos/*`, `esp_system.h`.

## Архитектура и принцип работы

### Структура файлов проекта

```text
├── index_html.h                # Веб-интерфейс дашборда (HTML, CSS, JS в формате PROGMEM raw string)
├── portal_html.h               # Страницы Captive Portal для настройки Wi-Fi (PORTAL_HTML, PORTAL_OK_HTML)
└── readme.md
```

### Опрос устройств (Multitasking FreeRTOS)

Опрос оборудования вынесен в отдельную фоновую задачу `pollMinerTask` (FreeRTOS Task, приоритет 2, стек 8192 байт), что предотвращает зависание основного веб-сервера при сетевых задержках или таймаутах недоступных майнеров.

- Опрос каждого майнера из списка выполняется последовательно с интервалом `STATUS_INTERVAL_MS` (5000 мс).
- Между запросами к устройствам вызываются `vTaskDelay` и `taskYIELD()`, предотвращая срабатывание аппаратного сторожевого таймера (Watchdog).
- Диспетчер перезагрузок (`rebootMiner`) вызывается в той же задаче перед опросом очередного майнера, что исключает блокировку основного цикла.
- Состояние защищено мьютексом `stateMutex`; данные передаются через `MinerSnapshot` с проверкой `generation` (защита от гонок при удалении/пересоздании майнера).
- При недоступности Wi-Fi (3 с) или в режиме Portal задача «спит» и не потребляет ресурсы.

### Парсинг протоколов (Whatsminer vs Antminer)

Большинство майнеров отдают ответы по протоколу CGMiner/BMMiner (TCP 4028). Однако форматы данных и масштаб коэффициентов различаются.

**Единицы хешрейта:**

- В Antminer поля `GHS 5s` / `MHS 1m` / `GH av` передаются в гига-/мегахешах и делятся на соответствующие коэффициенты для перевода в TH/s. Дополнительно реализована эвристика по величине значения (`>500000 → /1e6`, `>500 → /1000`).
- В Whatsminer (особенно с BiXBiT) параметр `MHS av` исторически транслируется **уже в терахешах** (например, значение `125.74` означает 125.74 TH/s). Контроллер автоматически идентифицирует модель по полям `Miner Type`, `Factory GHS`, `Fan Speed Percent` и блокирует ошибочное масштабирование.

**Параметры Whatsminer:**

Контроллер извлекает расширенные метрики:

- паспортный хешрейт (`Factory GHS`);
- температуры блоков питания (`PSU Temp0..2`);
- температуру среды (`Env Temp`);
- напряжения/токи по входу и выходу PSU (`PSU Vin/Vout/Iin/Iout`);
- целевые и защитные температуры чипов (`Chip Temp Target`, `Chip Temp Protect`);
- процент заполнения ШИМ (`Fan Speed Percent`);
- раздельные обороты кулеров `In` / `Out` / `PSU`;
- память майнера (`Miner Memory Usage`);
- флаг штрафа No-Fee (`No Fee Pools Penalty Active`).

**Фоллбэк мощности Antminer:** если API не вернул ватты, для S19i подставляется 3100 Вт, для остальных S19 — 3250 Вт (паспортные данные).

**Парсинг температур Antminer S19:** поля `temp2_X` трактуются как температуры **чипов**, а `tempX` — как температуры **PCB** (плат). Также поддерживаются строковые поля `temp_chipX` и `temp_pcbX` формата `"58-59-60-61"` (дефисные диапазоны с усреднением).

### Телеметрия по хеш-платам (Chains, v2.2)

Для каждой из 4 хеш-плат парсятся и отдаются в API следующие поля:

- `id` — номер платы (1..4);
- `acn` — количество активных чипов;
- `rate_gh` — хешрейт платы (в GH/s);
- `hw` — HW-ошибки по плате;
- `freq` — частота (MHz);
- `temp_chip` — градиент температур чипов (например, `"58°→86°C"` для Whatsminer или дефисная строка для S19);
- `temp_pcb` — температура PCB;
- `bad_asic` — признак проблемы с чипами (содержит `x`/`X`/`-` в `chain_acs`).

Для Whatsminer источником телеметрии по платам является команда `devs` (а не `stats`, которая на BiXBiT не поддерживается), с фоллбэком на `stats` для Antminer.

### Расширенная телеметрия пулов (v2.2)

Для каждого пула (до 3) отдаются:

- `url` — адрес пула;
- `user` — воркер;
- `status` — `Alive` / `Dead` / `Unknown`;
- `active` — флаг `Stratum Active` (пул в данный момент майнит);
- `diff` — сложность (`Diff` или `Stratum Difficulty`, приведённая к K при значении >= 1000);
- `accepted` / `rejected` / `stale` — счётчики шар.

Веб-интерфейс подсвечивает приоритетный пул с `status = "Dead"` красным бейджем и выводит предупреждение в карточке майнера.

### Механизмы перезагрузки

Процесс перезагрузки майнера устойчив к различиям прошивок.

**Для Antminer:**

1. Попытка отправки TCP JSON-RPC команды `{"command":"reboot","id":1,"parameter":["true"]}` на порт 4028.
2. В случае неудачи — каскадный обход 9 веб-эндпоинтов (включая `/cgi-bin/reboot.cgi`, `/cgi-bin/reboot_system.cgi`, `/cgi-bin/luci/admin/system/reboot`, `/api/reboot`, `POST /api/system/reboot` с JSON) с использованием HTTP Digest Auth (RFC 2617 с динамическим вычислением хэшей `HA1`, `HA2`, генерацией `cnonce` и счётчика `nc`). Пароли по умолчанию перебираются: `root/root`, `admin/root`, `root/admin`, `admin/admin`.

**Для Whatsminer:**

1. Выполняется вызов `/cgi-bin/luci/admin/status/btminerstatus/restart` через HTTPS (порт 443, SSL без валидации цепочки сертификатов `setInsecure()`) с Basic Auth.
2. При неудаче Basic Auth производится эмуляция веб-логина: `POST /cgi-bin/luci` с получением авторизационной cookie (`sysauth_https` или `sysauth`) и повтором команды.

**Общее поведение очереди перезагрузок:**

- Результат перезагрузки (`reboot_result`) хранится в статусе майнера до 180 секунд (TTL `REBOOT_MSG_TTL_MS`) или до 30 секунд после возврата майнера в онлайн.
- Очередь перезагрузок защищена от повторной постановки (сервер вернёт `409 reboot already queued`).

### Хранение настроек (NVS)

Конфигурация сохраняется в энергонезависимую память (NVS) микроконтроллера через интерфейс `Preferences` (пространство имён `minerctl`):

- настройки Wi-Fi (SSID, пароль, флаг статического IP, IP, шлюз, маска, DNS1, DNS2);
- логин и пароль администратора веб-интерфейса;
- массив из 8 структур `MinerConfig` (тип, имя, IP, порт, логин, пароль);
- ключ смены пароля (`w_pwd`) — пишется отдельным вызовом с проверкой `written == length`.

При первом запуске (если `w_cfg = false` или SSID пуст) плата поднимает точку доступа `MinerControl-Setup` с паролем `1234567890` и Captive Portal на `192.168.4.1`.

### Система логирования

Класс `LogTee` (наследник `Print`) перехватывает вывод и сохраняет его в статический кольцевой буфер `s_logRing` размером **64 КБ** (`LOG_RING_SIZE = 64 * 1024`). При переполнении старые байты вытесняются, счётчик `s_logDropped` учитывает объём overwritten-данных.

- Отдельный фильтр `s_logMinerFilter` (`-1` = все, `0..7` = конкретный майнер) применяется к записи **сырых ответов** от майнеров (`logMinerResponse`), но не к системным сообщениям.
- Потоковая передача лога (`logStreamToClient`) отдаёт корректный UTF-8 (с BOM), заголовок с метаданными и не рвёт многобайтовые символы при чтении из кольца.
- Доступно скачивание `.log`-файла (`/api/logs?download=1`) с именем `esp32-minerctl-uptimeXXXXXXs.log`.

## Инструкция по сборке и прошивке

### 1. Настройка Arduino IDE
1. Перейдите в **Файл -> Настройки**.
2. В поле *Дополнительные ссылки для менеджера плат* добавьте:
   ```text
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```
3. Откройте **Инструменты -> Плата -> Менеджер плат**, найдите `esp32 by Espressif Systems` и установите версию **не ниже 3.0.5**.
4. Установите необходимые библиотеки через **Инструменты -> Управлять библиотеками**:
   - `ArduinoJson` (выберите версию 7.x.x).
   - `ElegantOTA` (версия 3.x.x).

### 2. Параметры платы в меню "Инструменты"
- **Board:** `ESP32C6 Dev Module`
- **Flash Size:** `16MB (128Mb)`
- **Partition Scheme:** `16M Flash (3MB APP/9.9MB FATFS)` или **`OTA 8MB`** (рекомендуется для обновления по воздуху)
- **Upload Speed:** `921600` (или `115200` при проблемах с кабелем)
- **USB CDC On Boot:** `Enabled` (если используете встроенный порт Type-C)
- **Port:** выберите соответствующий COM-порт вашей платы.

### 3. Компиляция
Откройте `ESP32_MinerController.ino` и нажмите **Загрузить** (Ctrl+U).

## Первый запуск и настройка (Captive Portal)

1. **Включение точки доступа**:
   При первом включении (или если сохраненная сеть Wi-Fi недоступна) контроллер переходит в режим точки доступа (AP):
   - **SSID:** `MinerControl-Setup`
   - **Пароль:** `1234567890`
   - **IP адрес:** `192.168.4.1`

2. **Подключение:**
   Подключитесь к сети `MinerControl-Setup` со смартфона или ПК. Окно авторизации (Captive Portal) откроется автоматически. Если этого не произошло, перейдите в браузере по адресу:
   ```text
   http://192.168.4.1
   ```

3. **Конфигурация сети:**
   * Нажмите кнопку «🔍 Сканировать сети Wi-Fi поблизости» и выберите вашу сеть (поддерживается ручной ввод SSID при скрытой сети).
   * Введите пароль от Wi-Fi (до 64 символов, можно оставить пустым для открытой сети).
   * При необходимости отметьте чекбокс «Использовать статический IP» и укажите IP, маску, шлюз и DNS. На сервере выполняется валидация IPv4-конфигурации (проверка класса адреса, маски, принадлежности шлюза и IP к одной подсети).
   * Нажмите кнопку **«💾 Сохранить и подключиться»**.

Плата сохранит параметры в NVS и перезагрузится.

## Работа с веб-интерфейсом

После подключения контроллера к вашей локальной сети перейдите в браузере по имени:
```text
http://miner-control.local/
```
*(Либо по IP-адресу, который выдал роутер).*

### Авторизация

По умолчанию установлены следующие учетные данные для входа в панель:

* **Логин:** `admin`
* **Пароль:** `capybara2026`

Авторизация — HTTP Digest (RFC 2617). Пароль можно сменить в разделе «Настройки».

### Основной дашборд

#### Информационная панель (Header)

Отображает ключевые параметры контроллера:

- IP-адрес ESP;
- уровень сигнала Wi-Fi (RSSI);
- аптайм контроллера;
- количество подключённых майнеров (x/8);
- индикатор Live с heartbeat-счётчиком.

#### Сводная панель (Summary Bar, v2.2)

Показывает агрегированные метрики по всем онлайн-майнерам:

- общий хешрейт (сумма по онлайн-майнерам);
- общая мощность;
- энергоэффективность (**J/TH**, взвешенная по хешрейту и мощности);
- количество устройств в сети (Online / Total);
- максимальная температура (чипов или PSU) с цветовой индикацией:
    - зелёный — < 75 °C;
    - жёлтый — 75–85 °C;
    - красный — ≥ 85 °C.

#### Карточки майнеров

Каждая карточка содержит подробную информацию об устройстве:

- индикатор онлайн/оффлайн со счётчиком времени с момента последнего успешного обновления;
- хешрейт (мгновенный / средний / номинальный в зависимости от модели);
- потребляемая мощность и КПД (J/TH);
- температуры:
    - для Antminer — раздельно чипы (средняя/максимальная) и платы PCB;
    - для Whatsminer — зоны блока питания и входящий воздух;
    - подсветка меняется по порогам (зелёный → жёлтый → красный);
- шары (Accepted / Rejected), процент брака, Stale, HW-ошибки;
- **блок хеш-плат (Chains):** по каждой плате — хешрейт, количество чипов, HW-ошибки, градиент температур чипов, признак «битые ASIC»;
- **блок пулов:** статус (`ACTIVE` / `BACKUP` / `DEAD`), URL, воркер, сложность, количество принятых шар;
- блок PSU (для Whatsminer): вход/выход (V/A), название БП;
- обороты вентиляторов (In / Out / PSU) и процент ШИМ для Whatsminer;
- кнопка **«🔄 Перезагрузить»** с защитой от случайного нажатия и выводом статуса прохождения команды.

### Раздел «Настройки»

#### Сканирование сети

Запуск автоматического поиска майнеров в подсети `/24`. Найденные устройства можно добавить в конфигурацию в один клик.

> Для сетей с маской, отличной от `/24`, сервер вернёт `400 Auto scan supports /24`.

#### Ручное добавление/редактирование

Форма позволяет настроить параметры устройства:

- указание имени устройства (до 96 символов);
- выбор типа:
    - `Antminer S19/T19`;
    - `Whatsminer M30/M50 (BiXBiT)`;
    - `Antminer L3+/L3++`;
- ввод IP-адреса и порта API (`0` = авто: 4028 для TCP, 80 для HTTP);
- учётные данные для доступа к API майнера (можно оставить пустыми для дефолтных);
- чекбокс «Сбросить сохранённый пароль».

#### Смена пароля веб-интерфейса

Форма смены пароля содержит поля:

- текущий пароль;
- новый пароль;
- подтверждение нового пароля.

Ограничения:

- длина — 8–64 байта UTF-8;
- без управляющих символов;
- новый пароль не должен совпадать с текущим.

Новый пароль применяется также к OTA. После сохранения ESP перезагружается (~15 секунд).

#### Сброс настроек

Кнопка полной очистки NVS-памяти и возврата к режиму Captive Portal.

### Окно системных логов

Доступно по кнопке **«📜 Логи»** в верхней панели дашборда.

#### Просмотр логов

- Отображает содержимое кольцевого буфера сообщений (**64 КБ**) в реальном времени.
- Поддерживает автоскролл вниз и автообновление (каждые 2 секунды).
- В шапке лога выводятся метаданные:
    - фактический размер буфера (`retained`);
    - объём вытесненных данных (`overwritten`);
    - текущий фильтр по майнеру (`miner_filter`, `-1` = все);
    - пометка о возможной частичности самой старой записи.

#### Фильтр по майнеру

- Выпадающий список **«Записывать ответы: Все майнеры / #N · Имя · IP»** управляет фильтром сохраняемых сырых ответов (`/api/logs/filter`).
- Значение `-1` — записывать ответы всех майнеров.
- Значение `0..7` — записывать только ответы указанного майнера.
- Фильтр применяется только к новым записям; уже сохранённые в буфере данные не изменяются.
- Действие фильтра распространяется на все открытые вкладки браузера.
- Если указанный майнер не активен, сервер вернёт `404 Miner not found`.

#### Управление логами

- **«💾 Сохранить как .log»** — скачивание текстового файла лога. Имя файла формируется как `esp32-minerctl-uptimeXXXXXXs.log`, где `XXXXXX` — текущий аптайм ESP в секундах.
- **«🗑 Очистить»** — очистка кольцевого буфера в памяти контроллера (`POST /api/logs/clear`). Счётчик `overwritten` при этом обнуляется.
- **«✕ Закрыть»** — закрывает модальное окно и останавливает автообновление.

#### Особенности кольцевого буфера

- Размер буфера — **64 КБ**. При переполнении старые записи вытесняются, счётчик `s_logDropped` учитывает объём overwritten-данных.
- Первая строка в буфере может быть частичной — это нормальное поведение кольцевого буфера после вытеснения.
- Потоковая передача лога (`logStreamToClient`) отдаёт корректный UTF-8 (с BOM) и не рвёт многобайтовые символы при чтении из кольца.
- Для каждого ответа майнера в лог добавляется блок с метаданными

## Описание REST API

Все эндпоинты защищены HTTP Digest авторизацией (если не указано иное). В режиме Portal авторизация отключена.

| Метод  | URL                         | Описание |
|--------|-----------------------------|----------|
| `GET`  | `/`                         | Главная страница дашборда (HTML из PROGMEM). |
| `GET`  | `/api/status`               | Полное состояние всех сконфигурированных майнеров, метрик ESP, уровня RSSI и аптайма (JSON). Включает `chains[]` и `pools[]`. |
| `GET`  | `/api/config`               | Список сохранённых параметров майнеров (без вывода паролей, только `has_pass`). |
| `POST` | `/api/miner/save`           | Сохранение/обновление майнера. Принимает JSON `{idx, name, type, ip, port, user, pass}`. `idx = -1` — создать в свободном слоте. |
| `POST` | `/api/miner/delete/{idx}`   | Удаление слота майнера по индексу (0..7). Сбрасывает `minerGeneration[idx]`. |
| `POST` | `/api/reboot/{idx}`         | Постановка команды на перезагрузку майнера `{idx}` в очередь диспетчера. Возвращает `202 Accepted`, `409` если уже в очереди, `503` если задача опроса не запущена. |
| `POST` | `/api/scan/start`           | Инициализация фоновой задачи сканирования подсети `/24`. Возвращает `{running:true}`. |
| `GET`  | `/api/scan/state`           | Статус сканирования и список найденных устройств `{running, count, results[]}`. |
| `GET`  | `/api/logs`                 | Получение сырых данных из буфера логов. Параметр `?download=1` отдаёт как attachment `.log`. |
| `POST` | `/api/logs/clear`           | Очистка содержимого кольцевого буфера логов. |
| `GET`  | `/api/logs/filter`          | Получение текущего фильтра по майнеру `{idx, capacity_bytes}`. |
| `POST` | `/api/logs/filter`          | Установка фильтра `{idx:-1..7}`. `-1` = все, `0..7` = конкретный майнер. `404` если майнер не активен. |
| `POST` | `/api/web/password`         | Смена пароля веб-интерфейса. JSON `{current_password, new_password, confirm_password}`. Возвращает `{ok:true, restart:true}`, ESP перезагружается через ~1.5 с. Ошибки: `400` (невалидные поля/несовпадение/совпадение с текущим), `403` (неверный текущий), `500` (ошибка записи в NVS). |
| `POST` | `/api/reset`                | Полная очистка хранилища NVS (`minerctl`) и перезагрузка платы в режим AP. |

В режиме Captive Portal (AP) дополнительно доступны:

| Метод | URL | Описание |
|-------|-----|----------|
| `GET` | `/` | Форма первичной настройки Wi-Fi (`PORTAL_HTML`). |
| `GET` | `/scan.json` | Список Wi-Fi сетей поблизости `[{ssid, rssi, ch, enc}]`. |
| `POST` | `/savewifi` | Сохранение SSID/пароля/статического IP. Возвращает `PORTAL_OK_HTML` и через 3 с перезагружает ESP. |
| `GET` | `/generate_204`, `/gen_204`, `/connecttest.txt`, `/ncsi.txt`, `/hotspot-detect.html`, `/captive.apple.com`, `/canonical.html`, `/fwlink` | Captive-portal-probe (редирект на `/` или HTML-«Success»). |
| `GET` | `*` (NotFound) | Редирект на `http://192.168.4.1/`. |

## Диагностика и устранение неполадок

1. **Контроллер не подключается к Wi-Fi и уходит в режим AP.**
    - Проверьте, что сеть вещает в диапазоне **2.4 ГГц** (ESP32-C6 не поддерживает 5 ГГц сети).
    - Убедитесь в корректности пароля.
    - Если используется статический IP, удостоверьтесь, что адрес свободен и находится в подсети маршрутизатора (сервер валидирует конфигурацию при сохранении).

2. **Статус майнера `OFFLINE` или «Нет связи».**
    - Проверьте доступность порта майнера с помощью утилиты `ping` или `telnet <IP_майнера> 4028`.
    - В настройках Antminer проверьте параметр `api-allow` в конфигурационном файле `cgminer.conf` — API должен разрешать подключения с IP-адреса контроллера (например, `W:0/0` или указание подсети контроллера).
    - Для Whatsminer убедитесь, что TCP-порт 4028 открыт (по умолчанию может быть отключён в стоковой прошивке, у BiXBiT — активен).

3. **Whatsminer BiXBiT: неверный хешрейт / нет температур чипов.**
    - Убедитесь, что в настройках устройства выбран тип **Whatsminer M30/M50 (BiXBiT)**. Этот профиль предотвращает ошибочное деление терахешей на 10^6 и отправляет команду `devs` вместо `stats`.
    - Если `devs` не отвечает, будет выполнен фоллбэк на BiXBiT HTTP API (`/api/system/status`, `/api/pools`). Проверьте логи: в них отображается URL каждого HTTP-запроса.

4. **Не работают пулы / пустой блок Pool.**
    - Проверьте, что майнер отвечает на команду `pools` по TCP 4028. Для BiXBiT HTTP режима используется `/api/pools`.
    - В v2.2 добавлена поддержка статусов `Alive`/`Dead` и поля `Stratum Active`. Если приоритетный пул (P1) в статусе `Dead`, карточка майнера подсветится предупреждением.

5. **Ошибка при компиляции `StaticJsonDocument` / `JsonDocument`.**
    - Проверьте версию библиотеки `ArduinoJson`. Проект написан с использованием синтаксиса **ArduinoJson v7**. При использовании версии 6.x компиляция завершится с ошибкой.

6. **Переполнен лог / в начале видны «битые» символы.**
    - Буфер рассчитан на 64 КБ. При переполнении старые записи вытесняются, счётчик overwritten отображается в шапке лога. Первая строка может быть частичной — это нормальное поведение кольцевого буфера.
    - Для фильтрации по конкретному майнеру используйте выпадающий список в модальном окне логов.

7. **После смены пароля веб-интерфейс не отвечает.**
    - ESP перезагружается через ~1.5 с после успешного ответа `/api/web/password`. Подождите 15 секунд и обновите страницу.
    - Если страница не открывается — выполните сброс через кнопку «↩ Сбросить ВСЕ настройки + WiFi» при следующем входе, либо переподключитесь к `MinerControl-Setup`.
